## Пример 1: Простой однофайловый навык

### Сценарий
Генерация conventional commit сообщений из staged изменений.

### Структура
```
.claude/skills/commit-helper/
└── SKILL.md
```

### SKILL.md
```yaml
---
name: commit-helper
description: |
  Генерирует conventional commit сообщения из git diff.
  Используй при написании коммитов, просмотре staged изменений,
  или когда пользователь упоминает "коммит", "git commit",
  "сообщение коммита", "закоммить".
allowed-tools:
  - Read
  - Bash(git status)
  - Bash(git diff:*)
  - Bash(git log:*)
  - Bash(git add:*)
  - Bash(git commit:*)
user-invocable: true
---

# Генератор сообщений коммитов

## Инструкции

1. Запусти `git diff --staged` чтобы увидеть staged изменения
2. Проанализируй изменения и категоризируй:
   - `feat:` новые фичи
   - `fix:` исправления багов
   - `refactor:` реструктуризация кода
   - `docs:` изменения документации
   - `test:` добавление/изменение тестов
   - `chore:` технические задачи

3. Сгенерируй сообщение коммита:
   - Заголовок: макс. 50 символов, повелительное наклонение
   - Тело: объясни ЧТО и ПОЧЕМУ (не КАК)
   - Футер: ссылки на issues если применимо

## Формат

```
<тип>(<область>): <заголовок>

<тело>

<футер>
```

## Примеры

**Добавление фичи:**
```
feat(auth): добавить OAuth2 авторизацию

Реализованы провайдеры Google и GitHub OAuth.
Пользователи теперь могут входить через существующие аккаунты.

Closes #123
```

**Исправление бага:**
```
fix(api): обработать null ответ в user endpoint

Раньше падал когда у пользователя нет профиля.
Теперь возвращает пустой объект с дефолтными значениями.
```
```

## Пример 2: Многофайловый навык со скриптами

### Сценарий
Обработка и анализ PDF-документов.

### Структура
```
.claude/skills/pdf-processing/
├── SKILL.md
├── FORMS.md
├── REFERENCE.md
└── scripts/
    ├── extract_text.py
    └── validate_pdf.py
```

### SKILL.md
```yaml
---
name: pdf-processing
description: |
  Извлекает текст, заполняет формы, объединяет PDF, анализирует документы.
  Используй при работе с PDF-файлами, формами, извлечении текста,
  или когда пользователь упоминает "PDF", "форма", "документ",
  "извлечь текст", "пдф".
  Требует пакеты pypdf и pdfplumber.
allowed-tools:
  - Read
  - Write
  - Bash(python:*)
  - Bash(pip install:*)
context: fork
agent: general-purpose
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "python3 scripts/validate_pdf.py"
          once: true
---

# Обработка PDF

## Быстрый старт

Извлечь текст из PDF:
```python
import pdfplumber
with pdfplumber.open("doc.pdf") as pdf:
    text = pdf.pages[0].extract_text()
```

## Требования

Сначала установи зависимости:
```bash
pip install pypdf pdfplumber
```

## Возможности

1. **Извлечение текста** — Получить текст из любого PDF
2. **Заполнение форм** — Заполнение полей AcroForm в PDF
3. **Объединение** — Соединить несколько PDF
4. **Разделение** — Извлечь конкретные страницы

## Вспомогательные скрипты

**Извлечь текст:**
```bash
python scripts/extract_text.py input.pdf > output.txt
```

**Валидировать PDF:**
```bash
python scripts/validate_pdf.py input.pdf
# Возвращает: OK или детали ошибки
```

## Ссылки

- Работа с полями форм описана в `scripts/extract_text.py`
- [REFERENCE.md](REFERENCE.md) — Документация API
```

## Пример 3: Навык с Hooks

### Сценарий
Ревью кода с фокусом на безопасность и валидацией.

### Структура
```
.claude/skills/security-review/
├── SKILL.md
└── scripts/
    └── check_secrets.sh
```

### SKILL.md
```yaml
---
name: security-review
description: |
  Проверяет код на уязвимости безопасности, утечку секретов
  и проблемы из OWASP Top 10. Используй при аудите безопасности,
  ревью PR на безопасность, или когда пользователь упоминает
  "безопасность", "уязвимость", "аудит", "секреты", "OWASP",
  "security review".
allowed-tools:
  - Read
  - Grep
  - Glob
  - Bash(git diff:*)
  - Bash(git log:*)
hooks:
  PreToolUse:
    - matcher: "Read"
      hooks:
        - type: command
          command: "./scripts/check_secrets.sh $TOOL_INPUT"
  PostToolUse:
    - matcher: "Grep"
      hooks:
        - type: command
          command: "echo 'Просканировано: $TOOL_INPUT' >> /tmp/security-audit.log"
user-invocable: true
---

# Ревью безопасности кода

## Чеклист

### 1. Обнаружение секретов
- [ ] API-ключи, токены, пароли
- [ ] Приватные ключи, сертификаты
- [ ] Учётные данные БД
- [ ] AWS/GCP/Azure секреты

### 2. OWASP Top 10
- [ ] Инъекции (SQL, Command, XSS)
- [ ] Нарушенная аутентификация
- [ ] Утечка чувствительных данных
- [ ] XML External Entities (XXE)
- [ ] Нарушенный контроль доступа
- [ ] Неправильная конфигурация безопасности
- [ ] Cross-Site Scripting (XSS)
- [ ] Небезопасная десериализация
- [ ] Использование компонентов с известными уязвимостями
- [ ] Недостаточное логирование и мониторинг

### 3. Валидация ввода
- [ ] Санитизация пользовательского ввода
- [ ] Ограничения загрузки файлов
- [ ] Валидация параметров

## Формат отчёта

```markdown
## Отчёт по ревью безопасности

**Дата:** ГГГГ-ММ-ДД
**Ревьюер:** Claude Code
**Область:** [проверенные файлы/директории]

### Критические проблемы
[Список критических уязвимостей]

### Высокий приоритет
[Список высокоприоритетных проблем]

### Средний приоритет
[Список среднеприоритетных проблем]

### Низкий приоритет / Предложения
[Список мелких проблем и улучшений]

### Резюме
[Общая оценка состояния безопасности]
```
```

## Пример 4: Навык с context: fork и кастомным агентом

### Сценарий
Глубокое исследование кодовой базы и анализ архитектуры.

### Структура
```
.claude/skills/codebase-explorer/
└── SKILL.md
```

### SKILL.md
```yaml
---
name: codebase-explorer
description: |
  Глубокое исследование и анализ архитектуры кодовой базы,
  паттернов и зависимостей. Используй когда пользователь спрашивает
  "как работает X", "объясни архитектуру", "найди где реализовано X",
  "разберись в коде", "исследуй проект", или нужен комплексный анализ.
context: fork
agent: Explore
model: sonnet
allowed-tools:
  - Read
  - Grep
  - Glob
user-invocable: true
---

# Исследователь кодовой базы

## Миссия

Предоставить всестороннее понимание архитектуры кодовой базы,
паттернов и деталей реализации.

## Стратегия исследования

### Фаза 1: Обзор высокого уровня
1. Определить тип проекта (язык, фреймворк)
2. Построить карту структуры директорий
3. Найти точки входа (main, index, app)
4. Локализовать файлы конфигурации

### Фаза 2: Картирование архитектуры
1. Идентифицировать основные компоненты/модули
2. Построить карту зависимостей между компонентами
3. Найти общие утилиты и хелперы
4. Документировать паттерны потока данных

### Фаза 3: Глубокое погружение
1. Проследить реализацию конкретных фич
2. Документировать API endpoints и handlers
3. Идентифицировать используемые паттерны проектирования
4. Отметить потенциальные области улучшения

## Формат вывода

```markdown
## Анализ кодовой базы: [Название проекта]

### Обзор
- **Язык:** [Основной язык]
- **Фреймворк:** [Основной фреймворк]
- **Архитектура:** [Паттерн: MVC, микросервисы, и т.д.]

### Структура директорий
[Дерево с аннотациями]

### Ключевые компоненты
[Список с описаниями]

### Поток данных
[Диаграмма или описание]

### Точки входа
[Основные файлы и их назначение]

### Зависимости
[Ключевые внешние зависимости]

### Найденные паттерны
[Используемые паттерны проектирования]

### Рекомендации
[Потенциальные улучшения]
```
```

## Пример 5: Навык, вызывающий субагентов

### Сценарий
Оркестрация нескольких специализированных агентов для комплексных задач.

### Структура
```
.claude/skills/project-analyzer/
└── SKILL.md
```

### SKILL.md
```yaml
---
name: project-analyzer
description: |
  Комплексный анализ проекта с использованием специализированных
  субагентов. Анализирует качество кода, безопасность, архитектуру
  и документацию. Используй когда пользователь просит "полное ревью
  проекта", "комплексный анализ", "проверь весь проект", или хочет
  понять общее здоровье проекта.
context: fork
agent: general-purpose
allowed-tools:
  - Read
  - Grep
  - Glob
  - Task
user-invocable: true
---

# Анализатор проекта

## Многоагентный анализ

Этот навык оркестрирует несколько специализированных агентов
для предоставления комплексного анализа проекта.

## Рабочий процесс

### Шаг 1: Запуск параллельных анализов

Используй инструмент Task для запуска специализированных агентов:

```
# Анализ качества кода
Task(
  subagent_type="Explore",
  prompt="Проанализируй качество кода: паттерны, сложность, покрытие тестами"
)

# Анализ безопасности
Task(
  subagent_type="Explore",
  prompt="Найди уязвимости безопасности и утечки чувствительных данных"
)

# Анализ архитектуры
Task(
  subagent_type="Plan",
  prompt="Документируй архитектуру, зависимости и поток данных"
)
```

### Шаг 2: Синтез результатов

Объедини находки всех агентов в единый отчёт.

### Шаг 3: Приоритизация рекомендаций

Ранжируй находки по:
1. **Критические** — Уязвимости безопасности, утечка данных
2. **Высокие** — Архитектурные проблемы, проблемы производительности
3. **Средние** — Качество кода, поддерживаемость
4. **Низкие** — Стиль, документация

## Шаблон отчёта

```markdown
# Отчёт о здоровье проекта

## Резюме
[Обзор в 2-3 предложениях]

## Качество кода: [Оценка/10]
[Ключевые находки]

## Безопасность: [Оценка/10]
[Найденные уязвимости]

## Архитектура: [Оценка/10]
[Структурная оценка]

## Документация: [Оценка/10]
[Оценка покрытия]

## Топ-5 рекомендаций
1. [Самое критичное]
2. [...]
3. [...]
4. [...]
5. [...]

## Детальные находки
[Полный анализ от каждого агента]
```
```

## Быстрый справочник: Выбор сложности навыка

| Сценарий | Структура | Context | Agent |
|----------|-----------|---------|-------|
| Простые промпт/инструкции | Один SKILL.md | - | - |
| Нужна справочная документация | SKILL.md + reference файлы | - | - |
| Требуются утилитные скрипты | Много файлов с scripts/ | - | - |
| Сложный многошаговый workflow | Много файлов | `fork` | `general-purpose` |
| Исследование только для чтения | Один/Много | `fork` | `Explore` |
| Планирование архитектуры | Один/Много | `fork` | `Plan` |
| Кастомный специализированный агент | Много файлов | `fork` | Имя кастомного агента |
