# Справочник — Спецификация Frontmatter

## Официальная документация

**Основной источник**: https://code.claude.com/docs/en/skills 

При необходимости проверки актуальной информации используй WebFetch:
- GitHub примеры: https://github.com/anthropics/skills
- Best practices: https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices
## Поля Frontmatter

### Обязательные поля

| Поле | Тип | Макс. длина | Правила валидации |
|------|-----|-------------|-------------------|
| `name` | string | 64 символа | только строчные буквы, цифры, дефисы; без пробелов; без зарезервированных слов ("anthropic", "claude"); без XML-тегов |
| `description` | string | 1024 символа | не пустое; должно включать ЧТО + КОГДА (триггеры); без XML-тегов |

### Опциональные поля

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `allowed-tools` | list/string | все инструменты | Инструменты, которые Claude может использовать без запроса разрешения |
| `model` | string | наследуется | Переопределение модели: `sonnet`, `opus`, `haiku` или полный ID модели |
| `context` | string | - | Установи `fork` для изолированного выполнения в sub-agent |
| `agent` | string | `general-purpose` | Тип агента когда установлен `context: fork` |
| `hooks` | object | - | Lifecycle hooks: PreToolUse, PostToolUse, Stop |
| `user-invocable` | boolean | `true` | Показывать в меню `/` slash-команд |
| `disable-model-invocation` | boolean | `false` | Блокировать программный вызов через Skill tool |

### Поле disable-model-invocation

Используй для навыков, которые должны вызываться **только пользователем** через `/команду`, но не программно через Skill tool:

```yaml
---
name: dangerous-cleanup
description: |
  Удаляет временные файлы и кэши. Используй только по явному
  запросу пользователя "очистить кэш", "удалить временные".
user-invocable: true
disable-model-invocation: true  # Запретить вызов через Skill tool
allowed-tools:
  - Bash(rm -rf:*)
---
```

**Когда использовать:**
- Навыки с деструктивными операциями
- Навыки, требующие явного подтверждения пользователя
- Навыки для debugging/admin задач

## Паттерны разрешений инструментов (allowed-tools)

### Базовый синтаксис

```yaml
# YAML-список (рекомендуется)
allowed-tools:
  - Read
  - Grep
  - Glob

# Строка через запятую
allowed-tools: Read, Grep, Glob
```

### Паттерны для Bash-команд

| Тип паттерна | Синтаксис | Пример | Что совпадает |
|--------------|-----------|--------|---------------|
| **Точное совпадение** | `Bash(команда)` | `Bash(npm run build)` | Только эта команда |
| **Префикс** | `Bash(cmd:*)` | `Bash(git commit -m:*)` | `git commit -m "любое сообщение"` |
| **Wildcard** | `Bash(cmd *)` | `Bash(gh *)` | Все команды `gh` |

### Готовые наборы инструментов

**Операции только для чтения:**
```yaml
allowed-tools:
  - Read
  - Grep
  - Glob
```

**Git-операции:**
```yaml
allowed-tools:
  - Read
  - Grep
  - Glob
  - Bash(git status)
  - Bash(git diff:*)
  - Bash(git add:*)
  - Bash(git commit:*)
  - Bash(git push:*)
  - Bash(git log:*)
```

**Python-разработка:**
```yaml
allowed-tools:
  - Read
  - Write
  - Edit
  - Bash(python:*)
  - Bash(pip install:*)
  - Bash(pytest:*)
```

**Полный доступ на запись:**
```yaml
allowed-tools:
  - Read
  - Write
  - Edit
  - Grep
  - Glob
  - Bash
```

## Конфигурация Context и Agent

### Когда использовать `context: fork`

Используй форкнутый контекст когда:
- Сложные многошаговые операции, которые не должны засорять основной разговор
- Операции требуют другого доступа к инструментам чем родительский контекст
- Долгие задачи, которым полезна изоляция
- Навык генерирует обширный вывод

```yaml
---
name: code-analysis
description: Глубокий анализ кода с детальными отчётами
context: fork
agent: general-purpose
---
```

### Доступные типы агентов

| Агент | Инструменты | Назначение |
|-------|-------------|------------|
| `Explore` | Только чтение (Read, Grep, Glob) | Исследование, анализ кодовой базы |
| `Plan` | Только чтение | Планирование архитектуры, дизайн |
| `general-purpose` | Все инструменты | Сложные задачи с записью |
| Имя кастомного агента | Как определено в `.claude/agents/` | Специализированные workflow |

## Конфигурация Hooks

### Поддерживаемые события

| Событие | Когда срабатывает | Может блокировать | Может изменять |
|---------|-------------------|-------------------|----------------|
| `PreToolUse` | Перед выполнением инструмента | Да | `updatedInput` |
| `PostToolUse` | После завершения инструмента | Нет | - |
| `Stop` | Когда навык завершается | Нет | - |

### Синтаксис Hooks

```yaml
hooks:
  PreToolUse:
    - matcher: "Bash"              # Имя инструмента или regex
      hooks:
        - type: command            # "command" или "prompt"
          command: "./scripts/validate.sh $TOOL_INPUT"
          once: true               # Выполнить только раз за сессию
          timeout: 30              # Таймаут в секундах (опционально)

  PostToolUse:
    - matcher: "Write|Edit"
      hooks:
        - type: command
          command: "./scripts/lint.sh $TOOL_OUTPUT"

  Stop:
    - hooks:
        - type: command
          command: "./scripts/cleanup.sh"
```

### Переменные окружения в Hooks

- `$TOOL_NAME` — Имя вызываемого инструмента
- `$TOOL_INPUT` — JSON-ввод инструмента
- `$TOOL_OUTPUT` — Результат инструмента (только PostToolUse)
- `$CLAUDE_PROJECT_DIR` — Корневая директория проекта

### Коды выхода Hooks

| Код | Значение | Эффект |
|-----|----------|--------|
| 0 | Успех | Продолжить выполнение |
| 2 | Блокирующая ошибка | Заблокировать вызов инструмента, показать stderr Claude |
| Другой | Неблокирующая ошибка | Записать предупреждение, продолжить |

## Расположение файлов

### Где хранятся навыки

| Расположение | Путь | Область |
|--------------|------|---------|
| Персональные | `~/.claude/skills/` | Все твои проекты |
| Проектные | `.claude/skills/` | Этот репозиторий |
| Плагинные | `skills/` в корне плагина | Пользователи плагина |
| Корпоративные | Управляемые настройки | Вся организация |

### Порядок приоритета (от высшего к низшему)

1. Корпоративные (managed)
2. Персональные (`~/.claude/skills/`)
3. Проектные (`.claude/skills/`)
4. Плагинные

## Соглашения об именовании

### Имена навыков

```yaml
# ХОРОШО — существительные и составные слова
name: commit-helper
name: pdf-processing
name: security-review
name: codebase-explorer

# ХОРОШО — герундии (для процессо-ориентированных навыков)
name: generating-reports
name: analyzing-code

# ПЛОХО
name: helper              # Слишком размыто
name: My Skill            # Заглавные буквы, пробелы
name: claude-assistant    # Зарезервированное слово
```

### Структура директории

```
имя-навыка/               # Должно совпадать с полем `name`
├── SKILL.md              # Обязательный, регистрозависимый
├── reference.md          # Опциональная детальная документация
├── examples.md           # Опциональные примеры
└── scripts/
    └── helper.py         # Опциональные вспомогательные скрипты
```

## Сводка правил валидации

### YAML Frontmatter

- Должен начинаться с `---` на строке 1 (без пустых строк перед)
- Должен заканчиваться `---` перед Markdown-контентом
- Используй пробелы для отступов (не табы)
- Рекомендуется отступ в 2 пробела

### Поле Name

- Только строчные буквы, цифры, дефисы
- Максимум 64 символа
- Должно совпадать с именем директории
- Без зарезервированных слов: "anthropic", "claude"
- Без XML-тегов

### Поле Description

- Максимум 1024 символа
- Не пустое
- Должно включать:
  - ЧТО навык делает (возможности)
  - КОГДА его использовать (триггерные слова)
- Без XML-тегов
- Пиши от третьего лица, не от первого

### Пути файлов

- Всегда используй прямые слэши: `scripts/helper.py`
- Никогда не используй Windows-пути: `scripts\helper.py`
- Держи ссылки на один уровень вглубь от SKILL.md

## Быстрый шаблон

```yaml
---
name: my-skill-name
description: |
  [ЧТО] Делает X, Y и Z для конкретного сценария.
  [КОГДА] Используй при работе с [контекст], когда пользователь
  упоминает [триггер1], [триггер2] или спрашивает о [тема].
allowed-tools:
  - Read
  - Grep
  - Glob
context: fork                    # Опционально: для сложных операций
agent: general-purpose           # Опционально: с context: fork
model: sonnet                    # Опционально: переопределение модели
user-invocable: true             # Опционально: показывать в меню /
hooks:                           # Опционально: lifecycle hooks
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/validate.sh"
---
```
