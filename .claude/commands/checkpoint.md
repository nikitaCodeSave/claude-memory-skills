# ⏸️ CHECKPOINT: $ARGUMENTS

## Текущее состояние

Собери информацию о текущем состоянии проекта:

```bash
# Статус тестов
pytest -q 2>&1 | tail -10

# Изменённые файлы
git status --short 2>/dev/null || echo "Not a git repo"

# Последние изменения
git diff --stat 2>/dev/null | tail -10 || echo "No git history"
```

## Сводка

```
⏸️ CHECKPOINT: $ARGUMENTS

📊 Текущий статус:
   Тесты: X проходят / Y всего
   Изменённые файлы: <список>

📋 Последние изменения:
   <краткое описание что было сделано>
```

## Варианты действий

Предложи пользователю выбор:

```
Выбери действие:

[1] ✅ APPROVE — продолжить к следующей фазе
    → Одобрить текущее состояние и двигаться дальше

[2] 🔄 REVISE — внести изменения
    → Опиши что нужно изменить, и я исправлю

[3] 📝 EXPLAIN — объясни подробнее
    → Получить детальное объяснение текущего кода/тестов

[4] 🔍 REVIEW — показать код
    → Вывести содержимое конкретных файлов

[5] ⏪ ROLLBACK — откатить изменения
    → Вернуться к предыдущему состоянию

[6] ❌ ABORT — прервать workflow
    → Остановить TDD цикл полностью

Введи выбор (1-6) или опиши что хочешь:
```

## Обработка выбора

- **1 (APPROVE)**: Продолжи к следующей фазе TDD
- **2 (REVISE)**: Запроси детали изменений и выполни
- **3 (EXPLAIN)**: Объясни текущую логику кода/тестов
- **4 (REVIEW)**: Выведи запрошенные файлы
- **5 (ROLLBACK)**: Предложи `git checkout` или ручной откат
- **6 (ABORT)**: Подтверди прерывание и выведи статус

Если пользователь пишет свободный текст — интерпретируй как запрос на изменения.
